# MOLT 0.11.0 Alpha 3

This release advances the local QLoRA runtime across Qwen, Llama-family, and
Gemma-family model paths while keeping the implementation strategy proprietary.

## Customer-visible changes

- Added deterministic execution planning and reusable GPU execution paths.
- Added cross-family runtime qualification and stricter promotion gates.
- Reduced measured training time, board energy, and allocator peak versus the
  matched Unsloth diagnostic arms on the development system.
- Improved microbatch safety, checkpoint behavior, telemetry, and thermal
  enforcement.
- Added integrity verification to the Windows bootstrap installer.
- Added automated dependency auditing, static security checks, pinned release
  actions, and PyPI OIDC publishing.

## Evidence boundary

Six-pair diagnostic screens showed mean elapsed-time improvements of 38.42% for
Qwen, 46.54% for a Llama-family model, and 73.38% for Gemma. Allocator peaks were
8.13%, 5.66%, and 0.47% lower respectively. These are development-system
diagnostics, not universal claims. The official promotion gate remains open
until controlled graphics clocks, longer endurance, larger models, Soup, and
independent reproduction are completed.

Implementation details, internal scheduling diagrams, kernel derivations, and
private profiling records are intentionally excluded from this public note.

## Verification

- 361 public automated tests passed on Windows/Python 3.12.
- Bandit reported no high-severity source findings.
- `pip-audit` reported no known vulnerabilities among auditable dependencies;
  the CUDA-specific PyTorch wheel is outside PyPI's audit index.
- Tracked-file secret-pattern screening reported no high-confidence findings.
- Wheel and source distributions pass `twine check`.
