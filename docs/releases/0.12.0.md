# MOLT 0.12.0

MOLT 0.12.0 is a source-available research release focused on exact execution,
measurement, graph-memory experimentation, and thermal control for local QLoRA
training on consumer NVIDIA GPUs.

## What changed

- Added low-overhead per-update attribution for transformer graph replay,
  frozen-vocabulary loss, optimizer work, CUDA synchronization, graph-input
  staging, dataset transfer, Python dispatch, telemetry, and thermal pacing.
- Added exact frozen-vocabulary loss execution and partitioned-loss plumbing for
  large frozen language-model heads.
- Extended scheduled NF4 LoRA backward execution and its numerical gates.
- Added bounded gated-MLP replay and pinned-host activation-offload experiments
  to study graph-capture and steady-state memory.
- Added graph-capture memory accounting, shared-pool controls, and optional cache
  trimming after graph instantiation.
- Added heat-soak and closed-loop thermal pacing primitives with explicit safety
  validation.
- Added resident-memory tier planning based on original parameter counts and
  measured available memory.
- Expanded the qualified-path benchmark harness and exact trajectory checks.
- Updated the managed installer, documentation, and versioned one-command setup
  for `moltengine==0.12.0`.

## Verification

The pre-release local gate passed 447 tests on Windows/Python 3.12. The release
workflow repeats the full suite, builds one wheel and one source archive, checks
their metadata, and publishes to PyPI through trusted OIDC publishing.

Generated artifacts, model weights, prepared datasets, local environments,
trained adapters, caches, and internal profiling notebooks are not included in
the release.

## Current performance evidence

The latest clean one-million-target Qwen 1.5B, seed-2027 development pair used
the same initial adapter fingerprint and a fixed 140 W power limit. Relative to
the tested Unsloth arm, the qualified MOLT candidate produced:

| Metric | MOLT relative result |
| --- | ---: |
| End-to-end session time | 23.00% lower |
| Training throughput | 38.45% higher |
| Measured board energy | 1.07% lower |
| PyTorch allocated peak | 12.09% lower |
| PyTorch reserved peak | 9.37% lower |
| Sampled whole-GPU peak | 4.65% higher |
| Peak temperature | 7 C higher |

This is single-machine, single-seed development evidence. Graphics clocks could
not be locked, the framework versions differed between arms, and whole-GPU
memory can include driver-visible allocations outside the PyTorch allocator.
The result does not establish universal superiority. Five-seed, both-order,
controlled-clock endurance and independent reproduction remain required.

## Compatibility and safety

- Windows 10/11, 64-bit; Python 3.12.
- NVIDIA GPU with a compatible CUDA driver.
- Existing 0.11 managed installations can run `molt update` after 0.12.0 is
  available on PyPI.
- MOLT does not alter GPU clocks, drivers, antivirus configuration, or persistent
  power settings during installation.
- Validate each model and workload with `molt fit-test` before sustained use.
