# 0.9.2 — repaired command contracts and a coherent user workflow

Status: open-source alpha. These are correctness and usability changes, not a
new performance result or commercial reliability certification.

## Fixed

- Corrected all ten audited stale imports/signatures: generation, paired
  comparison, frontier, configured throughput, streaming, fusion, curriculum,
  exact-loss partitioning, power query, and QLoRA adapter benchmarking.
- CLI batch, context, and learning-rate overrides now apply to saved configs.
  Context overrides update both data and scratch-model geometry.
- Discovery hashes the checkpoint before displaying Verified; the same integrity
  primitive is used by the checkpoint store. Corruption is no longer mislabeled.
- Shared config parsing and mode-aware validation replace divergent loaders.
  QLoRA no longer inherits irrelevant scratch-model context restrictions.
- Workspace templates omit unsupported profile fields and use absolute paths.
- Both comparison commands honor --output using atomic JSON publication.
- Profile wording distinguishes pacing onset from the higher abort boundary.
- Simple help/version commands no longer import the checkpoint/PyTorch runtime.

## Added and simplified

- `doctor`: executable, package path, environment, Git commit when available, and
  hardware/dependency diagnostics. Legacy info/inspect remain compatible.
- `molt-workspace.json`: canonical workspace paths used by discovery. Removed
  developer-specific absolute paths. Existing templates/manifests are preserved.
- `research`: grouped experimental commands, retaining old top-level aliases.
- `prepare --text-file`: bounded UTF-8 tokenization with a local tokenizer,
  contiguous held-out token split, provenance hashes, and saved tokenizer files.
  Existing output directories are refused. This is not document-level splitting.
- `generate --prompt`: text input/output with the local base tokenizer, or an
  explicit --tokenizer for scratch models. Token-ID input remains available.
- `runs`, two-step `fit-test`, and verified `export` bundles. Exports exclude
  base weights/data and retain local config references; they are not standalone
  Hugging Face models. Review paths before moving or sharing a bundle.
- Guided resume lists interrupted runs rather than already-completed work.
- Presentation switches also work after commands, e.g. `doctor --ui`.

## Verification and limits

in a clean directory. The wheel and source distribution build successfully, and
the dependency lock validates. A local text-preparation -> generated QLoRA config
-> two-step fit-test also completed on Qwen. This is a smoke-level customer flow,
not evidence of useful adaptation or sustained throughput.

Automated coverage includes backend signature checks, fresh-workspace subprocess
training/evaluation/generation/export, all advertised commands' help entry points,
text preparation, corrupt-checkpoint discovery, and simulated thermal-boundary
resume equivalence. The CPU resumed run matches uninterrupted weights and RNG
exactly; this is not a physical power-failure or QLoRA-resume experiment.

Physical retests under `D:/Projects/MOLT TEST/Test 109/stability-retest` exercised
GPU throughput, NF4 streaming, fusion, exact-loss partitioning, curriculum, power
query (read-only), and actual ~494M Qwen adapter evaluation, text generation,
benchmarking, and export. Completed command execution is not evidence that a
research hypothesis or performance gate passed.

Fusion recorded an upstream `OverflowError: Python int too large to convert to C
long` for the CUDA-graph-enabled max-autotune mode on this Windows runtime. The

patch or universal Windows compatibility claim is made in this release.

Fresh-machine installer bootstrap, multi-hour thermal runs, forced power failures,
large-model fit, and full QLoRA resume equivalence remain unverified here.
