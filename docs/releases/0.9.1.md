# 0.9.1 — scoped host tuning and cooling consistency

Status: open-source alpha stability release, not commercial certification.

## Changes

- Prioritized mode temporarily changes only MOLT's Windows process priority.
  It restores priority on exceptions and normal completion. Dry runs and
  cancelled training never activate tuning. Other platforms keep standard priority.
- Removed automatic background-app suspension and Defender exclusions. This
  deliberately removes unsafe host mutations rather than relying on `atexit`
  after a crash. Existing exclusions need manual review in Windows Security;
  their ownership cannot be inferred safely. No user exclusions are deleted.
- Prioritized mode no longer overrides configured thermal boundaries or batch
  geometry. Resumes retain their recorded specification. Use explicit profiles
  for thermal choices instead of hidden mode-dependent changes.
- Removed unconditional intra-op and inter-op thread changes from both trainers.
  CPU-only training and callers retain their own PyTorch thread settings.
- Long QLoRA pauses use callback-independent temperature decisions, sample every
  half second, and return on recovery or an abort boundary. Pause metrics include
  actual elapsed time, not the originally requested duration. Short pauses retain
  their configured duration; missing telemetry is not interpreted as recovery.
- Removed fabricated VRAM estimates and universal safety/memory guarantees.
  Training kernels, optimizers, adapters, dataset loading, and checkpoint formats
  remain intact. Historical benchmarks are explicitly not equal-quality proof.
- Refreshed the reproducibility lock and package version. Wheels contain runtime
  code and license/metadata, not datasets, model weights, or run artifacts.

## Verification

Run from the repository with Python 3.12:

```powershell
uv sync --locked --extra dev
uv run pytest -o addopts='' -q
uv lock --check
uv build
git diff --check
```

Local regression run: **91 passed**. Tests include CPU training/checkpoint
integration, mocked priority restoration on failure, no tuning on dry-run,
unchanged CPU thread settings, and fake-clock cooling tests with and without UI
observers (recovery, abort, missing sensors, sleep overshoot). Tests no longer
suspend real apps or add real antivirus exclusions. Wheel and sdist builds pass.

No sustained QLoRA thermal benchmark, forced power-cut test, or new performance
comparison was run for this release. Software pacing is not a hardware safety
guarantee; aborted or killed processes may lose steps since the last checkpoint.
