# EXP-1030 — MOLT adaptive exact-loss partitioning

Date: 2026-09-02  
Decision: **memory mechanism survives; Milestone 3 time/energy gate rejected**

## Prior-art boundary

Token-chunked fused linear cross-entropy is established in Liger Kernel. Cut
Cross-Entropy (Wijmans et al., ICLR 2025) avoids global logit materialization
with a more specialized kernel. MOLT claims neither mechanism as novel.

The implemented contribution is a typed, exact, native-Windows PyTorch
fallback plus an observable Pareto selector. It is isolated from the stable
trainer and has no silent fallback.

## Exact algorithm

For hidden states H, classifier W, and targets y, ordinary training materializes
Z = HWᵀ for every token. MOLT partitions token rows, sums the exact CE in
forward, and recomputes each partition during backward. It accumulates dH and
dW, then returns them through one custom autograd boundary. The objective and
gradient are unchanged except for declared floating-point ordering effects.

## Results

| Workload | Chunk | Peak baseline | Peak candidate | Memory change | Update-time change |
|---|---:|---:|---:|---:|---:|
| 10.78M, batch 16×512 | 1,024 | 1.893 GB | 1.248 GB | −34.07% | +9.03% slower |
| 58.01M, batch 24×512 | 1,024 | 6.172 GB | 5.178 GB | −16.11% | +6.69% slower |

The small workload retained approximately 104k tokens/s in its short probe.
The larger workload remained above the 3.5 GB gate and below 35k tokens/s.
Short sequential NVML energy samples were temperature/order biased and are not
used for promotion.

## Compatibility result

The ordinary Liger dependency resolver requested Linux Triton, for which no
Windows wheel exists. A no-dependency installation intended to reuse
Triton-Windows produced zero-filled package sources and failed import with a
null-byte syntax error. The broken package was removed. Neither failure changed
the project dependency files.

## Conclusion

Exact partitioning is useful for memory-constrained shapes but does not yet
improve time or energy. It must not be enabled by default or called a Milestone
3 success. A genuine promotion would require an optimized Windows fused kernel
or proof that freed memory enables an identical-effective-batch geometry whose
end-to-end time and energy improve across paired seeds.
