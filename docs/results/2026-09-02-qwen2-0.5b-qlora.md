# Qwen2 0.5B local QLoRA validation

Date: 2026-09-02. Status: successful mechanism and narrow quality smoke test;
not a general model-quality or datacenter-competitiveness result.

## Workload

- Local base checkpoint: configured through `MOLT_QWEN_MODEL`
- Architecture: Qwen2 causal LM, 494,032,768 stored BF16 parameters
- Adaptation: bitsandbytes NF4 double quantization plus rank-8 LoRA
- Dataset: TinyStories validation text, deterministically Qwen-tokenized into
  4,256,695 training and 474,565 validation `int32` tokens
- Geometry: context 256, batch 2, accumulation 1, 20 optimizer updates
- Optimizer: AdamW over 4,399,104 trainable adapter parameters
- Hardware: RTX 4060 Laptop GPU, 8 GB VRAM; 16 GB system RAM
- Configuration: `configs/molt-stream-qwen2-0.5b-qlora-benchmark.json`

The prepared-data manifest records the source, split rule, counts, and SHA-256
digests under `data/prepared/qwen2-0.5b/manifest.json`.

## Identical-window quality comparison

`molt qlora-benchmark` evaluated the unchanged base and saved adapter over the
same eight batches (2,048 tokens per arm):

| Arm | Validation NLL | Perplexity |
|---|---:|---:|
| Unchanged Qwen base | 2.3243 | 10.2196 |
| MOLT adapter | 2.0052 | 7.4275 |

The adapter improved NLL by 13.73% on this narrow held-out slice. The comparison
does not establish generalization because it uses one seed, one short run, and a
small deterministic prefix of one validation corpus.

## Exact trained-data test

The same base-versus-adapter benchmark was run on the first eight training
windows (2,048 tokens per arm):

| Arm | Training NLL | Perplexity |
|---|---:|---:|
| Unchanged Qwen base | 2.2587 | 9.5711 |
| MOLT adapter | 1.4027 | 4.0660 |

This is a 37.90% training-NLL improvement, confirming that the adapter learned
the selected stream. A separate greedy completion test used the exact seen prompt
“Once upon a time, in a big forest, there lived a rhinoceros named Roxy.” The
reference continued “Roxy loved to climb”; MOLT continued “Roxy loved to play”.
It reproduced the first four continuation tokens exactly and matched 4/40 token
positions overall. The output remained grammatical and story-consistent, but it
did not memorize the complete reference passage.

## Command-path verification

- `inspect`: QLoRA, CUDA, bitsandbytes, PEFT, Transformers, and Triton detected
- `prepare`: mmap token file validated
- `train`: NF4 QLoRA run completed with atomic checkpoint
- `report`: machine-readable summary loaded
- `resume`: correctly rejected the already completed run
- `evaluate`: adapter checkpoint reloaded and evaluated after fixing QLoRA dispatch
- `generate`: adapter reloaded and produced readable TinyStories-style text
- `qlora-benchmark`: base/adapter controlled comparison artifact generated

Generated text from the smoke adapter began: “Once upon a time, there was a
young girl named Lily. She was very curious and wanted to”.

## Limitations and failed gates

- This is adaptation, not training Qwen from scratch.
- The current arbitrary-decoder QLoRA path does not use MOLT layer streaming.
- End-to-end throughput is far below the historical 35,000 tokens/s small-model
  gate; that gate is not realistic for this 494M QLoRA workload and geometry.
- Peak temperature stayed below the configured 75°C abort, but exceeded the 65°C
  cruise target. The short run therefore did not validate cruise stability.
- Peak process RSS exceeded 1.5 GB. This is total process memory including the
  Transformers/QLoRA runtime, not measured incremental dataset-map overhead.
- The speed figures are one run and must not be treated as a stable distribution.

## Reproduction

```powershell
uv sync --extra qlora --extra windows-fusion
.\.venv\Scripts\molt.exe --json inspect
.\.venv\Scripts\molt.exe --json prepare --config configs\molt-stream-qwen2-0.5b-qlora-benchmark.json
.\.venv\Scripts\molt.exe --json train --config configs\molt-stream-qwen2-0.5b-qlora-benchmark.json
.\.venv\Scripts\molt.exe --json qlora-benchmark --run RUN_DIRECTORY --batches 8
.\.venv\Scripts\molt.exe --json evaluate --run RUN_DIRECTORY
```
